# Configurable rules

Most numbers in this guide are **settings**: a super admin can change them through the admin API without a code release. Each setting has a schema, so a bad value is refused, and every change is audited with a reason.

Settings marked *not used yet* exist for features that aren't built. Settings marked *fixed in code* have a feature that works, but the code uses a fixed value instead of reading the setting, so changing it has no effect yet.

## Tenants and enquiries

| Setting | Default | Meaning |
| --- | --- | --- |
| `tenant.free_contact_credits` | 5 | Free contact credits per tenant, for life |
| `enquiry.post_expiry_access_days` | 90 | Days a tenant keeps an enquiry after the listing expires *(not used yet)* |
| `rate.enquiry_user_per_hour` | 10 | Enquiries per tenant per hour *(not used yet)* |
| `rate.enquiry_user_per_day` | 30 | Enquiries per tenant per day *(not used yet)* |

## Staff overrides

Support, finance, admin and super admin can **grant** a customer credits with a reason, up to the grant limit:

| Grant | Gives back |
| --- | --- |
| Tenant credits | Contact credits |
| Restore matching | Matching recommendations |
| Restore boost | A rank boost |
| Restore shoot | A photo shoot |

Staff can see a user's entitlements and their use, and **revoke the unused part** of a grant with a reason.
